**Reviewed 2026-10-25. Document-only research. No vendor executable or installer was acquired or run. Owner approved only continuing non-privileged research, after accepting the v44 plan with PASS / observations none.**

## Decision: NO-GO for WinDock bundled virtual Xbox backend today

The available evidence does not establish a single backend that meets all four non-negotiables simultaneously: (1) completely local/offline, (2) lawful WinDock redistribution, (3) acceptable Windows driver-signing and machine-trust requirements, (4) reversible uninstall without disrupting unrelated devices. This is a review finding, not a declaration that installation is impossible or illegal in all uses. It is not individualized legal advice.

## Documentary evidence and source-of-truth hierarchy

- **HIDMaestro repository licence (exact tag):** [LICENSE at v2.0.3](https://github.com/hifihedgehog/HIDMaestro/blob/v2.0.3/LICENSE) explicitly grants MIT permissions subject to notice conditions. The release archive's third-party notices and embedded usbip-win2 components remain to be reviewed *only if acquisition is later separately authorized*.
- **HIDMaestro signing:** [Official signing guide](https://hidmaestro.org/docs/reference/driver-install-and-signing/) describes locally generated self-signed trust and administrative installation. An SDK claiming no testsigning boot mode is not the same as production Microsoft signing.
- **HIDMaestro rollback source discrepancy:** [v2.0.3 release notes](https://github.com/hifihedgehog/HIDMaestro/releases/tag/v2.0.3) describe optional usbip2_filter removal with USB 3 root-hub restart; [generic removal documentation](https://hidmaestro.org/docs/start/removing-hidmaestro/) still says the root-hub filter always stays. Because these differ, **use the v2.0.3 release as the hazard upper bound**, not the generic page as evidence removal is nondisruptive. Confirm exact utility/version and shared usbip ownership before any future plan; do not execute vendor uninstaller --preview or --yes now.
- **libvirtualhid stable legal text (exact tag):** [LB-SAL 1.0](https://github.com/LizardByte/libvirtualhid/blob/v2026.914.1218.10/LICENSES/LicenseRef-LizardByte-SAL-1.0.md), [licence map](https://github.com/LizardByte/libvirtualhid/blob/v2026.914.1218.10/LICENSES/license-map.md), and [Windows driver instructions](https://github.com/LizardByte/libvirtualhid/blob/v2026.914.1218.10/docs/windows-driver.md) distinguish permissive MIT API code from Windows driver/broker/MSI. A user purchasing a licence does not automatically grant WinDock redistribution rights.
- **Microsoft signing distinction:** [Driver signing](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/driver-signing), [driver catalog hashes](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/catalog-files), and [attestation requirements](https://learn.microsoft.com/windows-hardware/drivers/dashboard/driver-signing-offerings) distinguish package integrity, trusted signatures, certification, and compatibility. Neither published SHA-256 nor vendor signing claims demonstrate approval on the owner's particular Windows build.

## Decision thresholds for any future feasibility change

1. **Legal:** For libvirtualhid, obtain explicit written authorization covering WinDock's actual distribution model and confirm machine-entitlement costs; otherwise hard stop. HIDMaestro MIT applies to tagged repository, but third-party notices and redistribution terms remain unreviewed.
2. **Security:** Confirm a driver-signing model acceptable without weakening Windows boot/security settings. Do not silently install a self-signed root; a refusal to modify machine trust blocks HIDMaestro trial.
3. **Offline:** Show that first installation, gamepad creation, reconnect/reboot and sustained gameplay work without cloud or licence-service access. Existing vendor marketing statements or limited offline grace periods do not constitute this proof.
4. **Rollback:** Identify exact driver store packages, shared USB host controller/filter ownership, uninstall effects, queued reboot removals and restoration plan. Root-hub interruption is a user-visible risk, even if an uninstall completes.
5. **Owner consent:** Separate explicit informed approval is required before even acquiring an installer or running an artifact inspection, and another consent gate before admin/driver/trust/virtual-controller operations.

If pursuing a deployable backend, resolve the specific third-party licence and signature questions in writing first; then prepare a separately approved binary inspection and isolated recovery plan. No new Windows/Android hardware test and no revision to the already accepted v40 audit are needed for this documentary checkpoint.
